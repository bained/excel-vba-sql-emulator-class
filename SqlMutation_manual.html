SqlMutation Class Manual

Purpose: отделен in-memory фасад за SQL-подобни INSERT и UPDATE операции върху Excel таблица.

Основен принцип: промените първо се извършват върху копие в паметта. Excel worksheet-ът се променя само при Commit.

Препоръчан workflow

Dim mutation As SqlMutation
Dim values As Object
Set mutation = New SqlMutation
Set mutation = mutation.AutoRange("Employees")
' INSERT или UPDATE в паметта
' Проверка на RowsAffected
mutation.Commit

Препоръчително е винаги да проверявате RowsAffected преди Commit.

Insert

Public Function Insert(ByVal values As Object) As SqlMutation

Добавя един ред в паметта. Аргументът е late-bound dictionary. Работи и върху header-only таблица без data rows.

Dim values As Object
Set values = CreateObject("Scripting.Dictionary")
values("EmployeeId") = 13
values("Name") = "Nikolay"
values("Department") = "IT"
values("Salary") = 3100
values("Active") = True
mutation.Insert values
Debug.Print mutation.RowsAffected
mutation.Commit

Липсващ header key става Empty; непознати keys се игнорират.

DeleteWhere

Public Function DeleteWhere(field, comparisonOperator, expectedValue) As SqlMutation

Премахва всички съвпадащи data rows от in-memory snapshot-а. Header row се запазва. При Commit trailing worksheet rows се изтриват физически, за да няма остатъчни данни.

Debug.Print mutation.RowsAffected mutation.Commit
DeleteWhere не променя worksheet-а преди Commit.

Builder-ът комбинира условията с AND и изисква поне един filter за Update/Delete.

mutation.Where("Department", "=", "IT").AndWhere "Salary", ">", 3000

Commit

Public Function Commit() As SqlMutation

Записва целия in-memory snapshot обратно в target range-а.

mutation.UpdateWhere "Department", "=", "IT", values
If mutation.RowsAffected > 0 Then mutation.Commit
Commit презаписва целия target range, включително header row.

Public Function Truncate(Optional ByVal confirm As Boolean = False) As SqlMutation

Премахва всички data rows, но запазва header row. Изисква explicit confirmation:

Ограничения

  • Commit logging е in-memory и се губи при унищожаване на обекта.
  • Commit презаписва целия target range.
  • Няма автоматична typed conversion policy като при SqlQuery.

Commit validation and atomic restore

SqlMutation works on an in-memory snapshot. Commit validates that the target worksheet, row count, column count, and original range values are unchanged before writing.

mutation.UpdateWhere "Department", "=", "IT", values
If mutation.RowsAffected > 0 Then mutation.Commit

If the worksheet is changed externally or the write fails, the original range backup is used for restore when possible. The commit log records SUCCESS or FAILED, including the error text.

Commit log

log = mutation.GetCommitLog()
mutation.ClearCommitLog

The log columns are Timestamp, Worksheet, Range, RowDelta, Status, and Error.

Run RunAllSqlMutationTests from SqlMutationTests.bas. The suite covers snapshot operations, rollback, commit validation, protected-sheet failures, atomic restore, builder precedence, typed filters, diagnostics, and INSERT policies.
